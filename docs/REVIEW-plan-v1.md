# 핫딜 허브(가칭 딜시세) 기획서 v1 검토 메모

- 검토일: 2026-10-25
- 대상: hotdeal-hub 기획서 v1 (16개 섹션, PDF 21p)
- 총평: 구조·출처 정책·백링크 설계는 완성도 높음. 착수 전 아래 "필수 수정" 5건은 반영 필요.

## A. 필수 수정 (Phase 1 착수 전)

### A-1. "시세 환산 이득률" 지표와 §7-3 정책이 충돌
- 정의: `buy_rate - (sale_price / face_value * 100)` = "할인 구매 후 매입 시세로 넘기면 남는 %p".
- 이는 사실상 현금화 차익 계산기이며, 카드 조건 딜(신한카드 1인 3매 등)에 붙으면 카드 결제 상품권 현금화 계산으로 읽힘.
- §1-3·§7-3·§15에서 "현금화 계열 T4 키워드 전면 배제"를 선언했는데, 핵심 차별화 지표가 그 프레임을 정면으로 만듦.
- 수정안:
  1. 명칭을 "시세 대비 할인 폭"(정보성)으로 바꾸고, 설명 문구를 "현재 매입 시세보다 N%p 낮은 가격" 수준으로 중립화.
  2. `conditions.cards`가 비어 있지 않은 딜(카드 결제 조건 딜)과 `cardmall` 카테고리에는 지표 미표시.
  3. 딜 상세 CTA "보유 상품권 시세 확인"은 유지하되, "구매 → 매도" 흐름을 한 화면에서 유도하는 문구는 제거.

### A-2. dedupe_key에 시간 창이 없음
- `culturland|gmarket|50000|46000`은 매주 반복되는 동일 조건 딜(상시 특가 재게시)이 1개 딜로 병합되어 `status`·`first_seen`이 오염됨.
- 수정안: 병합 조건에 `first_seen` 기준 72시간(상품권) / 카테고리별 창을 추가하거나, dedupe_key에 주차(ISO week) 버킷 포함.

### A-3. 수집 실패 시 빈 사이트 배포를 막는 가드가 없음
- 소스 전부 차단·파서 깨짐·rates.json 실패 시 현재 워크플로는 그대로 빌드·배포함.
- 수정안(워크플로 단계 추가):
  - 신규 deals.json의 active 딜 수가 직전 대비 50% 미만이면 배포 중단 + 텔레그램 운영 알림.
  - `last_updated`가 2시간 초과 시 사이트 상단에 "갱신 지연" 배너 자동 표시.
  - 텔레그램 발행 단계는 `continue-on-error: true` (알림 실패가 배포를 막지 않게).

### A-4. 네트워크 위젯이 "사이트와이드 링크"가 되면 §10-1 원칙 1을 스스로 위반
- 위젯(허브 링크 5개)이 모두의시세 전 페이지에 들어가면 금지한 격자 링크와 동일.
- 수정안: 위젯 노출 범위를 명시. 브랜드 시세 페이지에는 해당 브랜드 딜 위젯만, 홈 1곳에만 TOP 5. 그 외 페이지에는 미노출. §10-4 가드레일 표에 "위젯 노출 페이지 ≤ 브랜드 페이지 수 + 1"로 상한 명기.

### A-5. 제휴 고지 위치
- 쿠팡 의무 문구를 "페이지 하단"에만 두면 공정위 추천·보증 심사지침(경제적 이해관계 표시)의 "소비자가 쉽게 인식할 수 있는 위치" 요건에 약함.
- 수정안: 제휴 링크가 있는 딜 카드/CTA 바로 옆에 "제휴 링크" 라벨 + 상세 페이지 상단 고지 1줄. 하단 쿠팡 문구는 추가로 유지.

## B. 권장 수정

### B-1. 데이터 커밋 전략 (git 비대화·충돌)
- 30분마다 `data/` 커밋 시 연 최대 1.7만 커밋, deals.json 전체 재기록 반복.
- 권장: deals.json은 커밋하지 않고 배포 산출물(`/api/deals.json`)을 다음 실행 시작 때 라이브 사이트에서 가져와 상태를 복원. 장기 보존이 필요한 `history/*.jsonl`만 하루 1회 커밋.
- 커밋을 유지한다면 push 전 `git pull --rebase` 추가(수동 커밋과 경합 방지). `fetch-depth: 1`에서는 rebase가 실패할 수 있으므로 `fetch-depth: 0` 또는 `git fetch --unshallow` 필요.

### B-2. Cloudflare Pages Direct Upload 한도
- 배포당 파일 2만 개, 파일당 25MB 제한. `/deal/{id}/` 페이지가 누적되면 수개월 내 한도 근접.
- 권장: 종료 후 30일 지난 딜은 페이지 생성 자체를 중단(410 처리), 데이터만 history에 보존. `wrangler pages deploy dist --project-name=... --branch=main`으로 브랜치 명시(프리뷰 배포 방지).

### B-3. Tailwind CDN을 Phase 1부터 CLI 빌드로
- Actions에 이미 빌드 단계가 있으므로 Tailwind standalone CLI 1줄 추가로 끝남. CDN 런타임은 SEO 사이트의 LCP·CLS에 불리하고 공식적으로 프로덕션 비권장.

### B-4. 점수 산식의 소스 간 추천 수 정규화
- 뽐뿌·펨코·퀘이사존 추천 수 스케일이 다름. 소스별 최근 7일 중앙값으로 나눈 상대값을 `log()`에 넣는 방식 권장.

### B-5. 상세 페이지 상태별 CTA
- `status: ended`인 딜의 판매처/제휴 CTA는 비활성화하고 브랜드 허브 링크로 대체(죽은 제휴 링크 클릭 방지).

### B-6. 공개 저장소에서 blocklist.json
- 제외 요청자 연락처·사유가 들어가면 공개됨. 게시글 ID·소스 slug·반영일만 저장하고 요청 이력은 비공개 보관.

### B-7. MODOOSISE_RATES_URL을 secret으로 둘 이유 없음
- 공개 정적 JSON이면 `vars`로 충분. secrets는 토큰·키만.

### B-8. FAQPage 리치결과 기대치
- 2023년 8월 이후 구글은 FAQ 리치결과를 정부·의료 등 권위 사이트로 제한. 구조화 데이터 자체는 무해하나 노출 효과는 기대하지 말 것.

## C. 확인 필요 (착수 전 체크)

- 소스별 RSS 실존 여부: 뽐뿌 `rss.php?id=ppomppu`, 클리앙 `/service/rss/board/jirum`, 루리웹 게시판 RSS(기획서에 HTML로 되어 있으나 RSS 있음). 에펨코리아는 봇 차단이 강해 1차 소스에서 2차로 내리는 것 검토.
- 쿠팡 파트너스 Open API 사용 조건(최종 승인 단계) 확인.
- 저장소명: 기획서는 `increw01-alt/hotdeal-hub`, 현재 세션 저장소는 `increw01-alt/26.10.25hotdeal`. 어느 쪽을 쓸지 확정.
- 푸터 "통신판매업 신고번호": 허브가 직접 판매·중개하지 않으면 신고 대상이 아니므로 기존 사업체 번호를 그대로 쓸지, 항목을 뺄지 결정.
- 7월 상테크 분석(48,898건) 원본 데이터 보관 위치.

# 쇼핑몰 바로가기와 상품 이미지 설계

날짜: 2026-11-10
상태: 승인 대기

## 목표

방문자가 딜 카드에서 상품을 바로 알아보고, 커뮤니티 글을 거치지 않고 쇼핑몰 상품 페이지로 갈 수 있게 한다.

사용자 결정(2026-11-10):
- 쇼핑몰 주소는 커뮤니티 글 페이지에서 수집한다.
- 이미지는 쇼핑몰 상품 페이지의 대표 이미지(og:image)를 쓴다. 커뮤니티 글의 이미지는 쓰지 않는다.

이 결정은 D-16의 "제목과 링크만 수집"을 바꾼다. 새 결정 D-22로 기록한다.

## 조사 결과 (2026-11-10, 소스당 글 2건)

| 소스 | 쇼핑몰 주소가 있는 곳 | 형태 |
|---|---|---|
| 뽐뿌 | `a.scrap_bx_href` | `s.ppomppu.co.kr?...&target=<base64 주소>&encode=on` |
| 루리웹 | `.source_url a` | `web.ruliweb.com/link.php?ol=<URL 인코딩 주소>` |
| 클리앙 | 전용 칸 없음 | 본문의 첫 외부 링크. 레딧·블로그 링크가 먼저 나오는 글도 있음 |

쇼핑몰 8곳에 봇 UA로 상품 페이지를 요청한 결과:
- 대표 이미지를 줌: 롯데온, 삼성닷컴.
- 차단(403, 429): 지마켓, 네이버 브랜드스토어, 쿠팡.
- 응답은 하지만 이미지 없음: 11번가.
- 상품이 아닌 사이트 공통 이미지를 줌: 커버낫 행사 페이지.

따라서 **이미지는 일부 딜에만 붙는다.** 글이 가장 많은 쿠팡·지마켓·네이버는 이미지가 비고 자리 표시로 대신한다. 브라우저로 위장해 차단을 넘는 방법은 출처 정책상 쓰지 않는다.

## 범위

포함:
- 글 페이지에서 쇼핑몰 주소 추출(뽐뿌, 루리웹, 클리앙).
- 쇼핑몰 상품 페이지에서 대표 이미지 주소 추출.
- 카드·상세 페이지의 "쇼핑몰에서 보기" 버튼과 썸네일.
- API 필드 `shop_url`, `image_url`.
- 소개 페이지 출처 정책 문구, D-22.

제외:
- 이미지 파일을 우리 쪽에 저장하는 것(R2 등). 주소만 저장하고 브라우저가 쇼핑몰에서 직접 받는다.
- 글 본문 저장. 주소 하나만 뽑고 버린다.
- 제휴 링크로 바꾸는 것. 사이트는 수수료를 받지 않는다.
- 쇼핑몰 가격·품절 확인.
- 퀘이사존, 에펨코리아(현재 수집 안 됨).

## 구조

### 수집 경로: 중계 한 곳에서 처리

뽐뿌와 루리웹은 Worker IP가 막혀 GitHub Actions 중계로만 가져온다. 글 페이지도 같아서, 상세 수집은 세 소스 모두 **중계에서만** 한다. 경로가 하나라 단순하다.

중계 루프 한 번(60초)마다:
1. Worker `GET /__relay/pending`(토큰 필요)이 상세가 필요한 글을 최대 8건 준다. `{ source, post_id, post_url }`.
2. 중계가 글 페이지를 받아 쇼핑몰 주소를 뽑는다. 요청 사이 1.5초.
3. 주소가 있고 그 판매처가 이미지 조회 대상이면 상품 페이지를 받아 대표 이미지 주소를 뽑는다. 타임아웃 8초, 응답은 앞 300KB만 읽는다.
4. 결과를 `POST /__relay/details`로 보낸다. `[{ source, post_id, shop_url, image_url }]`. 실패도 `null`로 보내 시도 횟수를 올린다.

대기 글 조건:
- `deal_posts.detail_tries < 2` 이고 `shop_url IS NULL`.
- `first_seen`이 24시간 이내, 닫히지 않은 글.
- 최신 글 먼저.

하루 새 글은 300건 안팎으로 본다. 커뮤니티 요청이 글당 1회, 쇼핑몰 요청이 최대 글당 1회 늘어난다.

시작 전 확인: 세 커뮤니티 robots.txt가 글 보기 경로를 봇에게 허용하는지 본다. 막힌 소스는 상세 수집에서 뺀다(`sources.json`의 `detail: false`).

### 추출 규칙 (순수 함수, `worker/src/detail.ts`)

`extractShopUrl(source, html): string | null`
- 뽐뿌: `scrap_bx_href`의 href에서 `target`을 base64로 풀어 쓴다. `target`이 없거나 풀리지 않으면 null.
- 루리웹: `source_url` 안 링크의 `ol` 값을 URL 디코딩한다.
- 클리앙: 본문 영역의 외부 링크를 차례로 보고, 판매처 사전의 도메인과 맞는 첫 링크를 고른다. 없으면 제외 목록에 없는 첫 링크를 고른다. 제외 목록은 커뮤니티, 블로그·카페, 유튜브, 레딧, SNS, 지도, 뉴스 도메인이다.

`cleanShopUrl(url): string | null`
- `http:`, `https:`만 허용한다. 그 외와 커뮤니티 자기 도메인은 null.
- `utm_*` 쿼리만 지운다. 나머지는 손대지 않는다. 글쓴이가 넣은 단축 주소나 추천 코드는 그대로 둔다.
- 2,000자를 넘으면 null.

`extractOgImage(html, pageUrl): string | null`
- `og:image`를 읽어 절대 주소로 만든다. `//`로 시작하면 `https:`를 붙인다. `https:`가 아니면 null.
- 경로에 `og-image`, `og_image`, `logo`, `default`, `share`, `favicon`이 들어 있으면 사이트 공통 이미지로 보고 null.

판매처별 이미지 조회 여부는 `shared/brands.json`의 `image_fetch: false`로 끈다. 쿠팡, 지마켓, 옥션, 네이버 계열은 처음부터 끈다. 사전에 없는 판매처는 시도한다.

### 데이터 (마이그레이션 0003)

- `deal_posts.shop_url TEXT`, `deal_posts.detail_tries INTEGER NOT NULL DEFAULT 0`.
- `deals.shop_url TEXT`, `deals.image_url TEXT`.
- 인덱스 `idx_posts_detail_pending (detail_tries, first_seen)`.

딜의 `shop_url`은 그 딜에 처음 들어온 글의 값을 쓰고, 비어 있을 때만 다른 글의 값으로 채운다. `image_url`도 같다. 한 번 채운 값은 바꾸지 않는다.

### API

- 목록·상세의 딜에 `shop_url`, `image_url`(없으면 null).
- 상세의 `posts[]`에 `shop_url`.
- 기존 `deal_url`은 그대로 커뮤니티 글 주소다. 기존 사용처가 깨지지 않는다.

### 사이트

카드(일반 딜, 상품권 딜 공통):
- 왼쪽에 썸네일 72px. `loading="lazy"`, `referrerpolicy="no-referrer"`, `alt`는 빈 값. 이미지가 없거나 불러오지 못하면 판매처 이름 첫 글자를 넣은 자리 표시를 보인다.
- 제목을 누르면 지금처럼 우리 상세 페이지로 간다. 카드 혜택이 거기에 있다.
- `shop_url`이 있으면 카드 오른쪽에 "쇼핑몰 ›" 링크를 둔다.

상세 페이지:
- 주 버튼 "쇼핑몰에서 보기 (lotteon.com)". 괄호 안은 실제 이동할 도메인이다. 단축 주소면 그 도메인이 그대로 보인다.
- 보조 링크 "커뮤니티 원문 글". 묶인 글 목록은 지금처럼 유지한다.
- `shop_url`이 없으면 지금처럼 원문 글이 주 버튼이다.
- 버튼 아래 한 줄: "쇼핑몰 주소는 커뮤니티 글에 올라온 그대로입니다. 가격과 재고는 쇼핑몰에서 확인하세요."

외부 링크는 모두 `rel="nofollow noopener" target="_blank"`. 주소와 이미지 주소는 템플릿에서 이스케이프한다.

소개 페이지 출처 정책에 추가: 글 페이지에서 쇼핑몰 주소 하나만 읽고 본문은 저장하지 않는다는 것, 이미지는 쇼핑몰이 공유용으로 내놓은 대표 이미지 주소를 표시만 한다는 것, 커뮤니티나 쇼핑몰의 삭제 요청은 기존 절차로 받는다는 것.

## 오류 처리

- 글 페이지나 상품 페이지가 실패하면 시도 횟수만 올린다. 2회 뒤에는 포기하고 원문 글 링크로 남는다.
- 중계가 멈춰도 수집 본체는 영향이 없다. 대기 글이 쌓였다가 24시간이 지나면 빠진다.
- `POST /__relay/details`는 건당 값을 다시 `cleanShopUrl`로 검사한다. 중계를 믿지 않는다.
- 한 번에 받는 건수는 20건으로 제한한다.

## 테스트

- `detail.test.ts`: 소스별 추출(지어낸 HTML 조각), base64·URL 디코딩 실패, 클리앙의 제외 도메인과 사전 우선, `javascript:`·커뮤니티 도메인 거부, `utm_` 제거, og:image 상대·프로토콜 생략 주소, 공통 이미지 거부.
- API: 대기 목록 조건, 결과 반영(처음 값 유지, 시도 횟수), 토큰 없는 요청 거부.
- 사이트: 카드와 상세의 버튼 분기(`shop_url` 있음·없음), 썸네일 자리 표시, 주소 이스케이프.
- 로컬 Worker에 지어낸 글과 결과를 넣어 끝까지 확인한다.

## 알려진 한계

- 큰 판매처(쿠팡, 지마켓, 네이버)는 이미지가 없다.
- 클리앙은 본문 첫 링크를 고르므로 가끔 엉뚱한 주소가 잡힌다. 버튼에 도메인을 보여 주어 방문자가 알 수 있게 한다.
- 글쓴이의 추천 코드가 든 주소가 그대로 나간다.
- GitHub 예약 실행이 멈추면 상세 수집도 멈춘다.
- 이미지를 쇼핑몰에서 직접 불러오므로, 쇼핑몰이 외부 표시를 막으면 자리 표시로 바뀐다.
